# Notes API

A standalone Go HTTP API for a single user's notes. Uses only the Go standard
library and persists notes in a local JSON file. Requires Go 1.26 or newer.

From this directory:

```bash
go run ./cmd/notes-api
```

The server listens on `127.0.0.1:8080` and creates `data/notes.json` on first start.
Configure the address and file with flags:

```bash
go run ./cmd/notes-api -addr 127.0.0.1:9000 -data ./data/my-notes.json
```

Build a binary:

```bash
go build -o notes-api ./cmd/notes-api
./notes-api
```

Run only one server process per data file. Requests within that process are safe
to run concurrently. Each successful mutation is saved before the response;
restarting the server reloads the notes. Writes use a synced temporary file and
atomic rename, and invalid existing data causes startup to fail without
overwriting it. The file is rewritten on each mutation and all notes are held
in memory, making this suitable for small local collections.

The API has no authentication. The default address restricts access to the local
machine; use an authenticated reverse proxy if exposing it to other users.
`SIGINT` and `SIGTERM` shut the server down gracefully.

| Method | Path | Behavior | Success |
| --- | --- | --- | --- |
| GET | `/healthz` | Health response `{"status":"ok"}` | 200 |
| POST | `/notes` | Create a note | 201 |
| GET | `/notes` | List notes, newest created first | 200 |
| GET | `/notes/{id}` | Retrieve a note | 200 |
| PUT | `/notes/{id}` | Replace title and content | 200 |
| DELETE | `/notes/{id}` | Delete a note | 204, empty body |

Creation and updates require `Content-Type: application/json`. Their body accepts
only `title` and `content`. Titles are trimmed and must contain 1–200 Unicode
characters. Content is optional, preserves whitespace, and allows up to 10,000
Unicode characters. Omitting content in a PUT clears it. Request bodies are
limited to 64 KiB, including JSON encoding and whitespace.

Create a note:

```bash
curl -i http://127.0.0.1:8080/notes \
  -H 'Content-Type: application/json' \
  -d '{"title":"Shopping","content":"Milk and bread"}'
```

Example response (IDs and UTC timestamps are generated by the server):

```json
{
  "id": "5f474b61b00b407da32e7f22a3c40c35",
  "title": "Shopping",
  "content": "Milk and bread",
  "created_at": "2026-10-01T12:00:00Z",
  "updated_at": "2026-10-01T12:00:00Z"
}
```

The response includes a `Location: /notes/{id}` header. Use the returned ID:

```bash
curl http://127.0.0.1:8080/notes

NOTE_ID=replace-with-returned-id
curl "http://127.0.0.1:8080/notes/$NOTE_ID"
curl -X PUT "http://127.0.0.1:8080/notes/$NOTE_ID" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Shopping","content":"Milk, bread, and eggs"}'
curl -i -X DELETE "http://127.0.0.1:8080/notes/$NOTE_ID"
```

Lists return a JSON array, including `[]` when empty. Updates preserve the ID and
creation time and change `updated_at`. Errors return `{"error":"message"}`:
400 for invalid input, 404 for missing notes or endpoints, 405 for unsupported
methods (with an `Allow` header), 413 for oversized bodies, 415 for unsupported
content types, and 500 for storage failures. Internal storage details are logged
on the server and are not included in error responses.

Verify:

```bash
go test ./...
go vet ./...
go test -race ./...  # Requires a C compiler and CGO enabled.
```
